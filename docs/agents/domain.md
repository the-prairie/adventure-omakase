# Domain Documentation

Adventure Omakase uses a single product context across the monorepo.

## Before Exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read decisions under `docs/decisions/` that affect the area being changed.
- Proceed without warning when a context file does not yet exist.

## Vocabulary

Use terms as they are defined in `CONTEXT.md` and the canonical product plan.
Do not replace established domain terms with new synonyms.
When a needed concept is undefined, record the ambiguity for domain modelling rather than silently inventing terminology.

## Decision Conflicts

Surface any conflict with an existing decision explicitly.
Do not silently override an accepted decision in implementation or review output.
